# GitHub Copilot Instructions for Portfolio

This repository is a **.NET 10** project using **ASP.NET Core Blazor**, **Dapper**, **Clean Architecture**, and **.NET Aspire**.

## Stack

- **.NET 10 / C# 14** (target: `net10.0`)
- **Web:** ASP.NET Core Blazor
- **Data:** Dapper
- **Validation:** FluentValidation
- **Observability:** OpenTelemetry
- **API docs:** OpenAPI (built-in)
- **Orchestration:** .NET Aspire
- **Testing:** xUnit + mocks
- **Architecture:** Clean Architecture

## Architecture & Structure

- **Four layers:** Domain → Application → Infrastructure → API
- Dependencies point inward only
- Domain has **zero** external dependencies
- Match existing patterns before introducing new ones; ask before deviating

## Coding Conventions

- **Errors:** Use the **Result pattern** for expected failures (not-found, validation, conflict). Map to HTTP via `ProblemDetails` at the endpoint. Reserve exceptions for genuinely unexpected errors.
- **Async:** Every async method takes and passes a `CancellationToken`. Never block on async (`.Result`, `.Wait()`, `.GetAwaiter().GetResult()`). No `async void` except event handlers.
- **Mapping:** Write **explicit** mappings only (constructor / `Select`). Do not use AutoMapper.
- **IDs:** Use `Guid` keys.
- **Serialization:** Use **System.Text.Json** with source-generated contexts for hot paths. Do not add Newtonsoft.Json.
- **Modern C#:** Use primary constructors, collection expressions, records, and pattern matching where they genuinely improve the code—not for their own sake.

## Testing

- **Framework:** xUnit with mocks for isolated units
- **Boundaries:** Mock only boundaries you own
- **Database:** Do **not** use `UseInMemoryDatabase` or mock `DbContext`—use Testcontainers
- **Naming:** `Method_Scenario_ExpectedResult`
- **Assertions:** One logical assertion per test
- **Bug fixes:** Write a failing test first to reproduce the bug

## Do Not Suggest

- **AutoMapper** — write explicit mappings
- **Exceptions for control flow** — use the Result pattern for expected outcomes
- **In-memory database in tests** — use Testcontainers
- **Business logic in controllers/endpoints** — keep endpoints thin; logic lives in handlers/services
- **Magic strings/numbers** — use constants, enums, or the Options pattern
- **Sync-over-async** — stay async end to end
- **`#region` blocks** — if a file needs regions, split it
- **Newtonsoft.Json** — use System.Text.Json
- **Service locator** — use constructor injection
- **Over-abstraction** — no interface with a single implementation "just in case"

## Project Setup

- **Central Package Management:** Versions live in `Directory.Packages.props`; never pin versions in individual `.csproj` files
- **Nullable reference types:** Enabled solution-wide; treat warnings as errors
- **Analyzers + `.editorconfig`:** Enforced; run `dotnet format` and keep the build warning-free
- **Global usings:** Use for common namespaces; keep per-file usings minimal

## Common Commands

- Build: `dotnet build`
- Test: `dotnet test`
- Run: `dotnet run --project src/Api`
- Format: `dotnet format`
- Aspire: `aspire run`

## Workflow Preferences

- For non-trivial changes, provide a short **plan first** and wait for approval before editing
- Don't invent problems—leave code that's already correct and idiomatic alone
- Explain each change in one line (what + why)
